# 岩芯样本切片实验室

运行：

```bash
npm start
```

访问 `http://localhost:3025`。支持样本创建、切片任务、步骤记录和交付统计。

## 原芯裁切排样（/nesting）

在旧入口（`/`）保留的同时，新增 `/nesting` 排样台：录入每段原芯的长度、裂隙与污染区间，
以及待制切片的长度范围、允许方法和优先级，自动排出可行切割方案。

### 模型约定（单位 mm）

- 每段原芯两端各损失「端头损耗」，可用区间为 `[端头损耗, 段长 − 端头损耗]`。
- 裂隙与污染区间合并为缺陷区间，从可用区间扣除后得到若干可用窗口；**切片不可跨越缺陷区间**。
- 同一窗口内相邻两片之间消耗一个「锯缝」；窗口边缘不额外计锯缝。
- 切片先按最小长度排入；若窗口余料大于 0 且小于「最短余料」，切片在其长度范围内加长以吸收废料，
  吸收不完的计废料；余料 ≥ 最短余料视为可再用余料。
- 废料 = 用到段的端头损耗 + 缺陷长度 + 锯缝总长 + 不可用余料；切割次数 = 切片数 + 用到的段数。

### 优化目标（字典序）

1. 有效切片数最多 → 2. 已排切片优先级之和最大 → 3. 废料最少 → 4. 切割次数最少 →
5. 放置签名（按编号）字典序最小 —— 同分方案按编号稳定输出，重复排样结果一致。

「必切」切片为硬约束：排不下则整次排样失败并返回冲突列表，不生成任何部分方案。

### API

- `GET /api/nesting/state` — 录入、当前方案、版本列表
- `PUT /api/nesting/inputs` — 整体替换录入（非法录入 422，原录入不变）
- `POST /api/nesting/relayout` `{ baseVersion }` — 重新排样；成功生成新版本，
  `baseVersion` 过期返回 409，必切片不可行返回 422 且状态不变
- `GET /api/nesting/versions/:v` — 回看历史版本

所有写操作在服务端串行执行并配合 `baseVersion` 乐观锁：**并发重排仅一次成功**；
状态先算后写、临时文件改名落盘（`data/core-nesting.json`），**失败不留部分方案，重启不丢**。

```bash
npm test
```

启动独立实例实测：缺陷不可跨越、锯缝/端头损耗/最短余料边界、切片加长吸废料、
并列最优编号稳定、必切保留、并发仅一次成功、失败回滚、重启持久化与旧入口保留。
